# Code of conduct

## The short version

Be decent to people. Argue about the code, not about the person writing it.

## What that means here

Ringos is a technical project, and technical disagreement is welcome — a benchmark that contradicts a
claim in the README is the most useful thing you can bring. What is not welcome is anything that
makes the project a worse place to bring it: personal attacks, harassment of any kind, demeaning
remarks about someone's identity or experience, deliberate derailing, or publishing anyone's private
information.

Two things worth stating, because they come up in performance work:

- **"Wrong" is about the code.** Saying a design is slower, unsound or unnecessary is normal review.
  Saying it about the person is not.
- **Nobody owes you their time.** This is maintained by one person, unpaid. An unanswered issue is
  not an insult, and pressing for attention is not a strategy.

This applies in issues, pull requests, commit messages and any other space the project uses.

## Enforcement

Report anything that needs attention through GitHub's private reporting form:
[**Report a concern**](https://github.com/lolaf-org/ringos/security/advisories/new). It is the same form the
security policy uses, because it is the one private channel this repository has; say plainly at the top that
the report is about conduct rather than a vulnerability. Only the maintainer can see it.

The maintainer will look into it and respond in whatever way the situation calls for: a private word,
an edited or deleted comment, or a block from the repository for anything sustained or severe.
Decisions rest with the maintainer.
